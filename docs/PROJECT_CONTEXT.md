# Контекст проекта

Дата обновления: 2026-11-03.

## Цель и замысел

Автор создаёт новую самостоятельную игру на базе игры с открытым исходным
кодом Shattered Pixel Dungeon. Новая игра меняет жанровый акцент: это RPG
с открытым миром, множеством квестов и цельной историей, сохраняющая базовый
геймплей оригинала. По уточнению Автора от 2026-11-02 мир состоит из отдельных
секций с проходами вправо, влево, вперёд и назад между ними. Одна огромная
бесшовная карта не планируется; новые межсекционные переходы пока не реализованы.

Сюжет является продолжением приключений героя после событий оригинальной
Shattered Pixel Dungeon: герой уже достиг главной цели и вынес амулет на
поверхность. Новая игра рассказывает о том, что происходит с ним дальше.

Вместо случайно генерируемых этажей, наград, противников и других элементов
игрок должен встретить авторский мир, сюжет, квесты и заранее продуманные
ситуации без случайностей. Для новой игры создаются собственные противники;
противников оригинальной игры Автор использовать не хочет. Новых противников
планируется вводить постепенно. Квесты рассматриваются как способ знакомства
игрока с ними.

Новая игра — полностью самостоятельный проект. Старые сохранения не будут
поддерживаться. Сюжетная связь с оригиналом не означает перенос сохранённого
персонажа или необходимость проходить оригинальную игру для запуска новой.
По мере разработки будут удаляться подземельные уровни оригинала и другие
механики, которые не понадобятся для этого условного продолжения.

## Как применять этот замысел при разработке

- Оценивай новые системы по тому, помогают ли они создать открытый мир,
  цельную историю и авторские игровые ситуации.
- Случайная генерация, оставшаяся в исходном коде, описывает существующую
  техническую базу, а не обязательные правила новой игры.
- Повторяемая генерация с фиксированным seed сама по себе не выполняет
  требование авторского проектирования мира.
- Квесты с бабушкой и водой, с Дровосеком и застрявшей телегой и с Мироном
  и сеногрызом в стогах утверждены Автором. Остальные квесты, регионы и сюжетные повороты пока
  не определены. История Дровосека в пробном диалоге — черновое содержание
  для демонстрации общения.
- Сохранение базового геймплея не означает, что все правила roguelike
  автоматически переносятся в новую RPG. Судьба отдельных систем определяется
  дальнейшими задачами и решениями Автора.
- Не ограничивай архитектуру требованием совместимости со старыми сохранениями
  и не добавляй для них миграцию.
- Подземельные уровни и ненужные механики не требуется сохранять ради
  оригинала. Их удаление должно учитывать зависимости оставшегося игрового кода;
  конкретный порядок удаления пока не выбран.

## Техническая база

Репозиторий содержит многомодульный проект на Java с Gradle и libGDX.
Модули перечислены в [settings.gradle](../settings.gradle).

| Путь | Назначение в существующем проекте |
| --- | --- |
| `core/` | Общий игровой код и ресурсы. |
| `SPD-classes/` | Базовые классы движка и утилиты. |
| `android/`, `desktop/`, `ios/` | Платформенные части исходной игры. |
| `services/` | Сервисы, включая новости и обновления исходного проекта. |
| `core/src/main/assets/` | Графика, звук, шрифты и локализованные тексты. |

Наличие платформенного модуля не означает, что эта платформа выбрана
для выпуска новой игры. Название и идентификаторы исходной игры в коде
также не являются утверждённым названием нового проекта.

Руководства по сборке исходной базы:
[Android](getting-started-android.md),
[desktop](getting-started-desktop.md),
[iOS](getting-started-ios.md).
Эти руководства могут отставать от текущих Gradle-конфигураций.

## Порядок тестирования

Автор тестирует игру самостоятельно либо отдельно поручает тестирование агенту.
Без такой просьбы агент не запускает автотесты, игру или игровые сценарии
и не перехватывает управление экраном эмулятора или планшета. Компиляция, сборка и проверка diff
выполняются по необходимости при работе с изменениями.

После каждой успешной сборки APK агент проверяет `adb devices -l`
и устанавливает обновление через `adb -s <serial> install -r`.
По указанию Автора от 2026-11-02, если по Wi-Fi ADB подключён планшет
или телефон, APK устанавливается именно на него, даже при запущенном эмуляторе.
Если физических устройств не подключено, можно использовать локальный
Android-эмулятор. Serial выбранного устройства указывается явно.
Отдельное подтверждение установки не нужно; правило о запуске игры
и тестировании только по явной просьбе сохраняется.
